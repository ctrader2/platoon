# platoon

A terminal app (Rust, ratatui) for managing Claude Code and Codex sessions on Linux and macOS: every conversation in one
list, live shared sessions, projects, tasks (each one Claude Code or Codex session following a squad, a Markdown file of
steps; the squad's model decides the program), archive, themes. (Tasks were called tickets until 1.0: the user's word is "task" everywhere; the code keeps `tickets.rs`, `Ticket`
and `tk`.)

A personal `CLAUDE.local.md` (gitignored) may add a maintainer's own workflow on top of this file.

## Working rules

- **Discuss before building** anything non-trivial: plan, ask the questions that change the answer, then build.
- **Commit only when green**: `cargo test` fully passes (run it twice: a test that fails once is a race to fix, not to
  retry), `cargo build --release` has no warnings, `cargo fmt --check` finds nothing to change and
  `cargo clippy --all-targets -- -D warnings` passes. The commit message says why.
- If there is uncommitted work you did not write, find out what it is before building on top of it, and never sweep it into
  an unrelated commit (`git add` files by explicit path).
- Keep the file table below current when a source file is added or its job changes.
- A change to what the user sees or does updates the matching page in `guide/` (and the README front page if it mentions
  it) in the same commit.

## Safety (platoon runs against your real Claude Code and Codex setups)

Whoever runs the tests probably uses Claude Code, Codex and platoon on the same machine, so:

- Tests are hermetic: temp dirs for `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `PLATOON_CACHE_DIR` and `PLATOON_CONFIG_DIR`. Never
  write to the real `~/.claude`, `~/.claude.json`, `~/.codex`, `~/.cache/platoon`, `~/.config/platoon`, never read the real
  `~/.codex` (the user's Codex sessions and login are there), and never touch the real clipboard from a test. Every test
  that starts the binary sets `CODEX_HOME` and `PLATOON_CODEX_BIN` (`common::NO_REAL_CODEX`, or a test's own temp ones);
  never run the real `codex` (it spends the user's allowance).
- Never run `platoon setup` against the real config, never edit `~/.claude/settings.json`, and never `cargo install` or
  replace an installed `platoon` (Claude Code settings may point at it). Use `target/`.
- Never signal or kill a process you did not start: live `platoon host ... claude --resume ...` sessions, Claude Code
  itself, Codex and Codex's shared background server (`codex app-server`) may be running. Use `ps`; never broad `pkill -f`/`pgrep -f` patterns (they match your own shell).
- In a unit test the real folders cannot be reached: `usage::cache_dir`, `archive::config_dir`, `agents::claude::claude_root`,
  `agents::claude::claude_json_path` and `agents::codex::codex_root` panic (`usage::forbid_real_dir`), and with them `agents::Providers::here`. Code a test runs takes its folders as arguments: an `App`
  has its own (`App::host_dirs`), and looks for and starts hosts in them (`host::discover_in`, `host::launch`), never in
  the real `~/.cache/platoon/hosts` where the live sessions' sockets are.
- serde_json: mutable indexing (`v["a"]["b"]`) silently creates null keys. Use `get_mut`.

## Build and test

```
export PATH="$HOME/.cargo/bin:$PATH"     # each shell call starts fresh
cargo test                               # ~40s; tests/idle_stop.rs alone is ~20s
cargo build --release                    # must be warning-free
cargo fmt --check                        # the code is kept formatted: run `cargo fmt` to fix
cargo clippy --all-targets -- -D warnings  # no clippy warnings, tests included
shellcheck scripts/*.sh tests/fake-claude.sh tests/fake-codex-server.sh tests/fake-codex-exec.sh  # if you have it; CI's is older and warns about more (SC2015: use `if`)
```

`tests/fake-claude.sh` is the stand-in `claude -p` (records every call, answers from files) shared by `testkit::AiFake` and `tests/common`;
`tests/fake-codex-exec.sh` the stand-in `codex exec --json` (records every call and the schema file it was given, answers in
Codex's JSON events; `out`, `exit`, `hang` for the ways a call goes wrong) for `testkit::AiFake::codex` and `tests/tokens.rs`;
`tests/fake-codex-server.sh` the stand-in Codex app-server (records every line, answers from files; `hang`, `exit-at-once`) for
`testkit::CodexServerFake` and `tests/codex.rs`.

Test environment knobs: `PLATOON_CLAUDE_BIN` (a stand-in for `claude`; set, it also makes Claude Code count as installed:
`Term::spawn` sets `common::NO_REAL_CLAUDE`, a program that can't exist, unless a test names its own), `PLATOON_CODEX_BIN` (a stand-in for `codex`),
`CODEX_HOME` (Codex's folder), `PLATOON_SKIP_SETUP_CHECK=1`, `PLATOON_BADGES`,
`PLATOON_COLORS`, `PLATOON_IDLE_SECS_PER_MINUTE`, `PLATOON_CLIPBOARD`, `PLATOON_NOTES_QUIET_SECS`, `PLATOON_NOTES_MAX_LIFE_SECS`,
`PLATOON_NOTES_HELPER=off`, `PLATOON_NO_UPDATE_CHECK=1` (no version checks: no request to GitHub, no `claude --version`;
every test that starts the binary sets it, and a unit test's `App` never starts them), `PLATOON_EDITOR_PATH` (the only place the notes editors and `v`'s editors are looked for; `v`'s
tests put stand-in `code`/`hx` there: `tests/editor.rs`'s `hx` records what it was started with), `PLATOON_EDITOR_BIN`, and
`PLATOON_FORBID_REAL_EDITOR` (set by `Term::spawn`: no real editor, VS Code included, can start), `PLATOON_UNINSTALL_TTY` (the file `platoon uninstall` and `scripts/uninstall.sh` read answers from instead of `/dev/tty`), `PLATOON_UNINSTALL_TEST_HOME` (both refuse to run unless every folder is inside it; `tests/uninstall.rs` sets it), `PLATOON_UNINSTALL_FROM_SCRIPT` (set by the script: no last line about removing the program). A unit test's app finds no
`v` editors at all (`App::set_file_editors_for_test` gives it stand-ins). Run the whole suite twice before trusting it and fix races instead of retrying. In a terminal test, a frame arrives
as a stream and `wait_for` can return halfway through one: wait for every line you rely on (`Term::wait_for_all`) and
snapshot only from `Term::stable()` when the claim is about the whole frame (what is missing, what order, how many). A real `claude` cannot be
used in tests (trust-folder prompt): use `sh` or a fake script. The same for `codex`; `src/testdata/codex/` holds trimmed
real Codex 0.163 sessions and hook inputs (`testkit::World::codex_samples` copies them into a world's Codex folder), and
`conversation/` a longer one in the same record shapes with made-up content (outside `sessions/`: tests copy it in).

## CI

`.github/workflows/ci.yml` runs on every push to `main` and every pull request, on Linux, as jobs side by side: `checks`
(fmt, clippy, the release build, `scripts/check-versions.sh`, shellcheck), `linux` (the tests) and a build on the
minimum Rust (1.88, `rust-version`); warnings are errors (`RUSTFLAGS=-D warnings`). A run takes about 3 minutes. CI runs
the tests with cargo-nextest (`.config/nextest.toml`): `--profile ci`, every test binary in one pool of 16 threads (the
tests mostly wait), then `--profile ci-perf`, the scale checks (`perf::`) on their own, one per core, since they time
themselves and miss their limits beside the pool. No retries; a hung test is named at 60s and ended at 3 minutes.
Locally `cargo test` is the check; a test must pass both ways (nextest runs each test in its own process). macOS (arm64: test and release build) runs on pushes to `main` and when started by hand (`gh workflow run ci.yml
--ref main`), not on pull requests while the repo is private (10x minutes); once public, on pull requests too. Every
job has a `timeout-minutes` (checks 15, Linux tests 20, minimum Rust 15, macOS 25, deny 10, watch 5) so a hang cannot eat
the free minutes. A failing test's output is printed as it happens and again at the end, and every test runs after one fails.
Tests must hold on macOS too: no `/proc`, no GNU-only flags (`sed -i`, `date -d`), no `/bin/true`, no case-sensitive file
names, and a temp folder that may be under the home folder (paths there are shown from `~`).
`deny.yml` runs `cargo deny check` (`deny.toml`: licenses, advisories, crates.io only) with CI and weekly.
`codeql.yml` runs CodeQL (Rust and the workflows, no build) on pushes to `main`, pull requests and weekly; while the
repo is private it skips itself (code scanning needs a public repo or GitHub Code Security). Dependabot (`dependabot.yml`)
opens weekly grouped minor/patch updates for cargo and the actions.
`checked-with/claude-code` and `checked-with/codex` are the Claude Code and Codex versions platoon was last checked with
(compiled in: the notice when a user's is newer): README.md and the guide must name the same ones (`scripts/check-versions.sh`
fails CI otherwise, `tests/docs_versions.rs` tests it), so change them in one commit. `version-watch.yml` checks npm daily
for each (`@anthropic-ai/claude-code`, `@openai/codex`; `scripts/version-watch.sh <claude-code|codex>`) and opens an issue
"Check support for Claude Code X" or "Check support for Codex X" for a newer version; no workflow commits, pushes or edits
anything.
`release.yml` runs only on a pushed version tag (never on `main` or pull requests): written by `dist` from
`dist-workspace.toml` (`dist generate`, then put back its one hand edit, the permissions; see the file's top), it builds
the release binaries, the install script and the Homebrew formula (tap `ctrader2/homebrew-tap`, secret
`HOMEBREW_TAP_TOKEN`) and calls `publish-crate.yml` (crates.io trusted publishing; skipped until the repository variable
`CRATES_IO_TRUSTED_PUBLISHING` is `true`). Release notes come from `CHANGELOG.md`.
